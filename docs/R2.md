# Fotos en Cloudflare R2

Las fotos de perfil y las historias de las juntadas se guardan en un bucket **privado**
de R2. Nadie entra directo al bucket: el celular sube con un link firmado que vence en
5 minutos, y para ver una foto la app pasa por `/fotos/...`, que chequea permisos y
redirige a un link firmado que vence en una hora.

- `avatars/<userId>/...`: fotos de perfil (y las propuestas pendientes).
- `historias/<juntadaId>/...`: historias; las ven solo los que van, por 24 horas.

## Configuración (una sola vez)

1. **Crear el bucket.** Cloudflare → R2 → *Create bucket* → nombre `hay-estaca`,
   ubicación automática. R2 pide un medio de pago cargado aunque se use el plan gratis.

2. **Token de acceso.** R2 → *Manage API tokens* → *Create API token*:
   - Permisos: **Object Read & Write**.
   - Buckets: solo `hay-estaca`.
   - Anotar **Access Key ID** y **Secret Access Key** (el secreto se ve una sola vez) y
     el **Account ID** (está en la página de R2).

3. **CORS** (para que el celular pueda subir directo). Bucket → *Settings* →
   *CORS policy* → *Add CORS policy* → pegar:

   ```json
   [
     {
       "AllowedOrigins": ["https://hay-estaca.vercel.app", "http://localhost:3001"],
       "AllowedMethods": ["PUT"],
       "AllowedHeaders": ["content-type"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

4. **Que las historias se borren solas.** Bucket → *Settings* →
   *Object lifecycle rules* → *Add rule*:
   - Nombre: `historias-24hs`
   - Prefijo: `historias/`
   - Acción: **Delete uploaded objects after 1 day**

5. **Variables de entorno**, en el `.env` local y en Vercel (*Settings → Environment
   Variables*, para Production y Preview), y después un *Redeploy*:

   ```
   R2_ACCOUNT_ID=...
   R2_ACCESS_KEY_ID=...
   R2_SECRET_ACCESS_KEY=...
   R2_BUCKET=hay-estaca
   ```

Sin estas variables la app funciona igual: simplemente no aparecen los botones de fotos
ni las historias.
